# Symora

Choose the narrowest source that answers the task. A known file or declaration does not require a repository-wide map or index build. Run a command with `--help` for its detailed options.

## Find and inspect

```bash
symora search symbols AuthService --lang python --limit 5
symora symbols src/auth.py --symbol 'AuthService/login' --signature
symora refs src/auth.py:42
symora context src/auth.py:42 --callees --types --with-bodies --body-tokens 4000
symora diff-impact
```

- Use `search symbols` for names, `search ast` for syntax, and `search content` for strings, each confined to named files or directories with `--path`. `search symbols` answers a bare name from the index when the index matches it; a name the index does not match, and a path (`Class/method`, `Name[kind]`), also ask language servers and can carry `indexing`. It takes `--body` or `--signature` to read a known declaration whose file is unknown. Content search defaults to code; name a format with `--lang markdown`. Searches skip ignored and oversized files; content and AST search read hidden files inside the paths they are given, while symbol search refuses a hidden path.
- `symbols` and `map file` use the language server when available, otherwise AST declarations, which also answer a `--symbol` path the server's tree lacks; `backend` identifies the producer. `symbols <file> --depth 1 --refs` counts references for each listed declaration, a type's members included and what a function declares excluded; the parameters and locals a server nests under a function, method or constructor are not declarations and are not listed; `refs_status` marks a count that is a lower bound or names why none was taken. `--deterministic` never consults a language server: index, AST and file-scan sources answer, and a command that needs a server returns `unsupported`.
- In a git work tree (a clone, a directory inside one, a linked worktree), the first `search symbols` builds the index in `.symora/` under the directory it runs in, or waits for a build already running, and answers from it, so it takes as long as that build; later searches read the index. Anywhere else (a home directory, an unpacked tarball, a CI checkout without `.git`) it builds nothing: the answer rests on language servers, a hint says no index took part, and `search index build` builds one there. Where a build failed, or was still running after the wait, the hints say so too. Refresh with `search index build` (incremental) when a response says the index is behind the working tree; `--force` rebuilds everything.
- `map summary` is an optional orientation tool. It lists the packages workspace manifests declare (Cargo `[workspace]`, npm or yarn `workspaces`, `pnpm-workspace.yaml`, uv `[tool.uv.workspace]`, `go.work`) in `packages`, largest first, which is absent where none declares a workspace. Its `entrypoints` are those a manifest or the language's build declares — Cargo targets, Python scripts and `__main__.py`, `package.json` `bin` and `main`, a Go `main` package's `main.go` — each with its `kind` (`bin`, `lib`, `script`, `main_module`) and `name`; a file merely named like one (`app.py`, `index.ts`) is not listed. Its `hints` name a manifest that could not be parsed and a declared entrypoint that names no file. `map file` lists the tests that name a file, each with its `evidence`: a test file whose imports name it (`imports`; `imports_package` where a Go import path or a JVM wildcard names its package), a Go `_test.go` file beside it (`same_package`), or a Rust region compiled only under test (`test_region`, with its `line` and `end_line`). A file sharing its name is not listed. The section's hint says which tests that reading leaves out, and a language it does not read returns `unsupported`; `context <file>:<line> --tests` lists the tests referencing one declaration.
- `diff-impact [REV]` compares tracked working-tree changes with one revision, not a revision range; for a branch, pass `$(git merge-base main HEAD)`. `--staged` compares the git staging area instead of the working tree. Untracked files are in neither; a working-tree run names them in `hints`. `--path` analyses only the changed files its git pathspecs match — a file or directory, a glob such as `'*.py'`, or `':!dir'` to leave one out — and a rename when either of its paths matches; references and callers are still searched across the whole project. `changed_files_count` then counts the matched files and `excluded_files_count` the changed files left out, which nothing in the answer measures; a pathspec that matches no file tracked now or at the revision is refused. When `--max-symbols`, the `lsp.timeout_secs` budget or the response size cuts a large diff short, measure it a part at a time with `--path`. Read `unmeasured_files`, `excluded_files_count`, `incomplete`, and each row's `refs_status` and `callers_status`; `refs_status_counts` and `callers_status_counts` count the rows of each status, so a total is a lower bound by those rows alone. The rows, `changes`, are a list with `count`, `showing` and `truncated` like any other; with `--callers`, a changed function's, method's or constructor's `callers` is one too, read off the references its count was taken from (`callers_status: references_derived`): every callable whose code holds one, a use as a value counted like a call, an import or other reference outside a callable not at all; a row of another kind reads `not_callable`. `--call-hierarchy` asks the server's call hierarchy for every row instead, a second search per symbol. `callers` is absent where `callers_status` says no list was obtained. A row whose deletion was not identified has no `name` or `kind`; its `file` and `line` are the first line removed. `--max-symbols` bounds the added and modified symbols whose references are counted and, apart from them, the deletions listed, so a deletion never takes a counted symbol's place; the files it stops in or before are listed in `unmeasured_files`. Documentation and configuration files are listed in `unmeasured_files`, not broken into keys or headings; read their diff.

## Address the intended symbol

Lines and Unicode-scalar columns are 1-indexed; a position past its file's end is refused as `invalid_argument` stating how many lines, or characters on the line, the file has. Every result states its own position flat as `file`, `line`, `column`, the name start to pass back; a span adds `end_line` (inclusive) and `end_column` (exclusive) where the source states them, and a related position (`call_site`, `definition`, `target`) is a nested object of the same shape.

- For `refs`, callers/callees, implementations, context, and impact: `file:line` addresses the declaration on that line or its enclosing symbol. An explicit column addresses the exact token and resolves usages through their definitions. Header keywords/whitespace may address that declaration; empty body positions address nothing.
- `def`, hover, typedef, and rename are position-exact; an omitted column means 1. Take name positions from actual results. `typedef` lists every type the server names there, in its order: `Vec<Order>` names both `Vec` and `Order`, so read past the first item.
- A `--symbol` path is a bare name, a `Class/method` suffix, a `*/method` wildcard, or an exact `name_path`. A trailing `[kind]` selects one kind among same-named declarations (`Svc[class]`, not its constructors); a segment written wholly in brackets is a name (`Cache/[key]`). A block that adds members or conformances to a type declared elsewhere, a Rust `impl` or a Swift or Dart `extension`, is kind `impl` and named for that type (a Dart extension for itself), with its header (`impl Display for Circle`) as its signature: its members are `Circle/fmt`, and `Circle[impl]` selects the blocks rather than the type. Kinds come from whichever source answered, and the index and a server can differ (pyright reports `MAX_SIZE` as `constant`, the index as `variable`). Take a kind from `symbols <file>` for the file you act on, and treat a zero under `--kind` as unverified.
- Read the echoed target. `anchor_status` is absent when a declaration resolved; `binding` is a declaration absent from the document-symbol tree, such as a local, a parameter, or one the server's outline omits; `not_a_symbol` and `unavailable` resolved nothing, so the counts are about no declaration. Source edits address declarations, not body tokens.

## Interpret limits

Lists carry `count`, `showing`, and `items`. These markers qualify the answer; each is present only when set, so read an absent one as false. `incomplete` is the one marker that says a count is a lower bound because of the command's own caps or failures, including a call-graph walk's `max_depth_reached`, `callers_truncated`/`callees_truncated` or `failed_hops`:

| Marker | Meaning and next action |
|---|---|
| `truncated` | Found items were omitted; the hint names the cap that cut the list and how to list the rest. Narrow the query or follow it. |
| `incomplete` / `unread_paths` | Counts are lower bounds within the consulted sources; inspect the cause. |
| `coverage_gaps` | Named languages were not fully searched; use the indicated source or remedy. |
| `stale` / currency hints | The index is a snapshot; refresh before current enumeration. New files can require refresh even without stale returned rows. |
| `indexing` | `unconfirmed`: the server's workspace readiness was not confirmed throughout the query. Only a server that reports workspace status (rust-analyzer) confirms it, so other servers' answers carry `unconfirmed` and retrying does not clear it. `timed_out`: the readiness wait ended before the server reported status; retry once it is warm. Neither proves absence. |
| `refs_status` / a `diff-impact` row's `callers_status` | `indexing_degraded`: the count or caller list is a lower bound. `references_derived`: the callers were read off the row's references, which its `refs_status` qualifies, and are not verified calls; `not_callable`: the row is no function, method or constructor, so it lists none. Any other value says why none was taken, in the `coverage_gaps` reasons: `timed_out` ran out of the `lsp.timeout_secs` budget, `unsupported` is a capability the server lacks, and `unavailable` failed or was not asked. |
| `degraded_column` | Verify the source position before editing. |
| `body_omitted` | `token_budget` or `response_size`: read the complete source at the returned location, or adjust that budget. |

Requested bodies are complete or omitted. Context shares `--body-tokens` across target, callees, then types; `bodies_included` counts emitted section bodies. Missing bodies may also be unresolvable or absent in source. Token estimates are character-based, not model-specific. `output.max_response_chars` can remove bodies before list items; 0 disables that size target.

Static references and caller graphs do not prove runtime reachability, change safety, or executed test coverage. Inspect registration, reflection, structural Protocol implementations, serialization, and external contracts when relevant. Reference-derived callers are marked `callers_status: references_derived`; without call hierarchy, `callers` on a type or value reads `not_callable` and lists none, since its references are uses rather than calls. `callees --to` finding no chain to a type or value, or from one, marks that endpoint's `target_status` or `anchor_status` `not_callable` instead of answering `no_static_path`. `callers --no-fallback` and `diff-impact --call-hierarchy` require the server's call hierarchy. A Python `__init__` or `__new__` has no references of its own, since pyright reports `Circle(…)` as a reference to the class: its callers are read off the calls of its class and marked the same way, a lower bound its hint names, and `refs` counts only references to the method itself.

## Edit and verify

```bash
symora edit replace-body src/auth.py --symbol 'AuthService/login' --body - --dry-run < replacement.py
symora edit delete src/auth.py --symbol obsolete --expect-no-references --dry-run
symora rename src/auth.py:42:9 new_name --dry-run
symora diagnostics src/auth.py --with-context
```

1. Read the complete definition: `symbols <file> --symbol P --body`, or `search symbols P --body` when the file is unknown. `replace-body` takes the entire definition, signature and decorators included; an omitted body is not replacement text.
2. Run the edit with `--dry-run` and check `target_symbol`, `lines`, and `preview`.
3. Apply it. `replace-body`, `insert-before`/`insert-after` and `delete` accept `--with-diagnostics`, and symbol replacement and insertion `--verify-callers`; after `edit pattern`, `rename` or `actions apply`, run `diagnostics`.
4. If diagnostics or the project's checks fail, fix and repeat from step 2. A diagnostics response that carries `status` (`unconfirmed`, `unsupported`, `unavailable`) is not clean, whatever its count; `status` is absent only from a confirmed list. A file the edit did not change, such as a caller, can show its list from before the edit, and no response says whether it does: pyright and rust-analyzer compute the list when it is read, after symora's own edits but possibly before they hear of another tool's; other servers report a caller's list only once they check it again. rust-analyzer's list is its own analysis: use-after-move, lifetime errors and clippy lints come only from `cargo check` or `cargo clippy`. Run the project's checks before taking a clean list as evidence.

- Prefer a returned symbol path over line numbers for sequential edits. `insert-before`/`insert-after` take `--code`; AST pattern takes `--text`.
- Delete's `--expect-no-references` requires verified static reference freedom, so under `unconfirmed` it refuses: check `refs` yourself and delete without it. A static zero alone does not establish that code is unused.
- Rename applies under confirmed workspace readiness. Under `unconfirmed`, compare each file's `edit_count` in the `--dry-run` with `refs` for the target, which leaves out the declaration the rename also edits, then apply with `--accept-unconfirmed`; the response keeps the marker, so check that no reference kept the old name. `timed_out` permits previews only.
- `edit pattern` rewrites the syntax nodes a tree-sitter pattern matches in one file, so a repeated replacement leaves look-alike text in strings and comments alone. It replaces match 0 unless `--index N` or `--index all` selects others; `--index all` refuses overlapping matches.
- `actions list <file:line:col>` lists the server's code actions at a position; `actions apply <file:line:col> '<title>' --dry-run` previews one by its exact title.
- `rename` and `actions apply` check every file before writing any, but a write that fails partway leaves earlier files modified; the error's hint names them, so inspect those before retrying.

## Recover

Failures emit `{ "error": { "code", "message", "hint" } }` on stdout and exit nonzero; logs use stderr.

- On `server_not_installed` / `lsp_unavailable`, run `doctor <lang>` and read `serves`, not only `installed`. A configured absolute server command avoids a broken version-manager shim. After project config changes, `daemon restart --project` unloads only this project's sessions; its next request starts fresh servers. Active requests or pending server startup return `conflict`. Changes to the daemon's own configuration or inherited environment require a full `symora daemon restart`, which also unloads every other project's sessions; ask the user before running it.
- For persistent cross-package omissions, verify the project's environment and native server configuration. `doctor python` reports the supplied selection in `python_interpreter`; `serves` confirms only the handshake. Waiting does not prepare an environment, and a missing `.venv` alone does not prove a fault.
- On `unsupported`, choose an index, AST, or content-search alternative. On `conflict`, wait as directed and re-read. On `cancelled` with a content-change hint, resolve the target again. Repair `precondition_failed` and `config_errors` before depending on the result.
- `lsp.timeout_secs` is the shared LSP work budget: startup, requests, and retries consume it together. Narrow expensive queries or configure a larger budget; it does not lengthen the readiness wait, and repeated calls do not add a missing capability.

Output is one-line JSON when stdout is not a terminal; `--format pretty` indents it. `--check-version '<requirement>'` enforces a binary contract. Put global flags (`--format`, `--check-version`, `--deterministic`) after the subcommand (`symora refs src/auth.py:42 --format pretty`), where the allowed-tools patterns match.
